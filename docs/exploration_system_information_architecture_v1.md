# 探索系统研究信息架构 v1（NR-01）

日期：2026-07-18  
状态：负责人已确认四页方向；本稿据此重写，作为 NR-02 的产品输入  
上位依据：原始一期研究方案、负责人本轮决定、中央数据与证据边界  

本文件冻结的是研究系统的产品结构，不是最终视觉设计。旧版 `route_map.svg` 与
`wireframe.html` 是此前六页面族探索记录，已退出冻结交付，不作为 NR-02 的依据。

## 1. 产品定义

本前端不是另写一套研究内容的网站，而是后端研究数据、关系结构、证据状态与时间
结构的自动化可视化客户端。

数据流固定为：

```text
中央研究表
  → NR-02 数据适配、状态控制与验证
  → 版本化前端 view model
  → 四个可视化引擎
  → 全局证据抽屉与时间层
```

前端不得直接读取几十张中央 CSV 后自行解释研究语义。它只渲染 NR-02 输出的前端
对象、关系、状态、标签和解释边界。中央研究表仍是事实源，前端派生数据不得反写。

这里的“自动化”指：

- 数据更新后，节点、连线、筛选、状态、时间与图注可重复生成；
- 同一对象在四页中使用同一 ID、名称、状态和来源；
- 图形选择和过滤不需要为每个案例另写网页；
- 自动渲染不等于自动推断联盟、因果、影响力或历史连续性。

## 2. 与一期研究图景的关系

一期主问题不是“做一张地图”，而是：

> 冲绳民间组织如何把基地问题转译为环保、生活安全、地方自治、人权、法律程序和
> 国际倡议等议题，并在关键地点和制度场域中发挥公开角色？

产品结构据此使用一句总原则：

> 地图是入口，组织是行动主体，转译路径是研究主线，证据是结论边界。

原方案的研究生产模块不直接变成页面。四个页面是同一研究数据的四种读法：

| 页面 | 研究动作 | 一期图景 |
|---|---|---|
| 总览 | 哪里发生了什么 | 地点—议题＋与那国／先岛 |
| 组织 | 谁以什么功能参与 | 组织分类＋组织—议题网络 |
| 路径 | 议题如何被组织并进入场域 | 共同行动、国际、法律、公投、行政等路径 |
| 证据 | 我们凭什么这样展示 | 覆盖偏差、来源边界、人工状态 |

1972 年以来的历史不是第五个主页面。它是四页共用的时间层；一期只显示已核历史锚点
与资料缺口，完整组织谱系仍属于扩展研究。

## 3. 冻结的页面数量

主展示页固定为四个，首页就是“总览”，不另设欢迎页。

| ID | 页面／路由 | 页面问题 | 主可视化引擎 |
|---|---|---|---|
| P1 | 总览 `/` | 哪里正在发生什么？ | V1 全域地点—议题研究地图 |
| P2 | 组织 `/actors` | 谁在参与，以什么功能参与？ | V2 组织—议题生态图 |
| P3 | 路径 `/pathways` | 行动如何进入事件与制度场域？ | V3 问题—行动—场域—产出路径图 |
| P4 | 证据 `/evidence` | 当前材料能支持什么、遗漏什么？ | V4 证据覆盖与偏差图 |

只有这四个主路由。地点、组织、议题、episode、来源和比较结果都在当前页面的选择状态、
右侧面板或抽屉中展开，不增加并列主页面。必要时可以用 URL 参数保存选择，例如
`/actors?actor=A002`，但它仍是组织页。

## 4. 四个主可视化引擎

“一页一张主图”指一套可交互的视觉引擎，不是每页只能输出一张静态 PNG。图层、筛选、
聚焦和比较改变同一张图的状态，不产生新的栏目。

### V1 全域地点—议题研究地图

默认首页，继承 `okinawa_regions_research_map_v1.png` 的视觉语法和第二张意向稿的交互
构图：中央全域画布、右侧阅读面板、底部时间层。

主图包含：

- 冲绳本岛、宫古、石垣、与那国等地理骨架；
- 地区研究问题、相关议题、组织入口与材料状态；
- “全域”“严格证据”“先岛聚焦”三个状态，而不是三个页面；
- 仅在严格证据状态绘制同源 actor–place–issue 事实；
- 右侧面板显示当前地区的组织、议题、路径入口与证据边界。

地图是探索入口，不用颜色表示政治立场，不以节点数量表示活动强度。区域短命题必须来自
版本化数据字段，不在前端代码中另写地区文章。

对应一期核心图：

- 地点—议题图；
- 与那国／先岛专题图。

### V2 组织—议题生态图

本页把“组织分类”和“组织—议题网络”合为同一视觉引擎。

主图包含：

- 当前选择范围内的 registry actor；
- 按功能、法律身份、origin、地点和议题形成的分面或群组；
- 人审 actor–issue 边、角色和事件参与；
- 选中组织后的议题、地点、episode 与证据足迹；
- “生态”“议题连接”“两对象比较”等图形状态。

默认不一次铺开 122 个 actor，不以中心性或面积表示影响力。共同联署、共同声明和同场
参与必须显示具体关系类型，不得画成无类型“联盟边”。

对应一期核心图：组织—议题网络。

### V3 问题—行动—场域—产出路径图

本页承载一期最核心的“转译”研究主线。

统一图形语法：

```text
地方问题／议题
  → 组织表达与行动
  → 事件或程序
  → 制度场域／行动对象
  → 中间产出
  → 有限结果／底层改变
```

法律、环境程序、公投、联署、国际倡议、行政协作和选举接口是筛选条件或路径类型，不是
独立页面。箭头必须区分观察顺序、正式角色关系与分析假设；进入场域不等于成功，程序
产出不等于政策改变，请求不等于机构回应。

对应一期核心图：国际倡议／法律程序路径图。

### V4 证据覆盖与偏差图

上一版把“命题—来源证据链”设为此页主图，现修正为一期合同明确要求的覆盖偏差图。

主图从时间、地域、actor 类型、议题、来源类型与证据等级显示：

- 哪些范围材料较深；
- 哪些范围仅有候选或二手材料；
- 哪些范围需要当地检索；
- 来源稀疏与行动稀少不可互相替代；
- source publication date、event date、claim period 分开。

点击任一覆盖单元后，右侧面板列出相关对象与来源；单条命题的完整证据链通过全局证据
抽屉展开，不再占用一张主页面。

对应一期核心图：覆盖偏差图。

## 5. 共用交互外壳

四页使用同一构图，不为每页另造一种产品：

- 顶部：四项导航、全局搜索、演示层／研究层状态；
- 中央：当前页面唯一主图；
- 右侧：当前选择的结构化详情面板；
- 底部：可展开时间层；
- 任一事实标记：打开全局证据抽屉。

选择状态跨页保留。典型路径为：

```text
全域地图选择“与那国＋地方自治”
  → 组织页只显示相关行动者
  → 路径页只显示相关事件与制度入口
  → 点击任一事实打开证据抽屉
```

比较不是第五页。用户在总览、组织或路径页选择两个同类对象后，主图进入同字段比较状态。

## 6. 文案与数据边界

前端不准备案例长文、地区专稿或模块摘要。允许的文字只有：

1. 固定界面文本：页名、问题、筛选、图例、操作提示；
2. 数据显示字段：名称、别名、类型、地点、议题、日期、角色、状态；
3. 版本化短命题：地区或 episode 的一行 `display_summary`；
4. 固定边界模板：`interpretation_limit`、证据等级说明和状态警告。

`display_summary` 和 `interpretation_limit` 属于 NR-02 数据契约，不硬编码在组件中。需要人
判断的短命题由负责人冻结；前端可以自动显示，不能自动创作。

首页禁止项目介绍长文、模块说明、统计卡片墙和报告式发现清单。项目定位压缩为标题、副标题
和一行样本边界。

## 7. 前端对象模型

前端只认识以下八类核心对象：

| 对象 | 作用 |
|---|---|
| actor | 组织级 registry actor；event-only 与制度节点保持独立类型 |
| place | 地点、区域与制度场域中的空间节点 |
| issue | 受控议题分类 |
| episode | 可核查的事件／程序／行动单元 |
| venue | 法院、行政、国际机构、公投、议会等场域 |
| outcome | 中间产出、有限结果、底层改变 |
| evidence | 来源、locator、等级、归档、人审与解释边界 |
| historical_anchor | 形成、改名、分裂、合并、连续性或缺口锚点 |

所有对象统一携带：

`id`、`display_label`、`display_summary`、`display_status`、`review_status`、
`evidence_level`、`source_ids`、`interpretation_limit`、相关日期语义和版本信息。

NR-02 应进一步输出面向四个视觉引擎的 view model，而不是让浏览器现场拼接研究关系。

## 8. 演示层与研究层

默认演示层只显示：

- `accepted`；
- `human_checked`；
- `source_backed_bounded`，且同时显示边界句；
- 作为缺口信息显示的 `local_retrieval_gap`。

研究层可以增加 `candidate`、`analytical_seed`、event-only 名称与待审项，但必须持续显示
状态标记。切换研究层只增加对象，不改变演示层的措辞或关系类型。

全局禁止：

- 候选边伪装成正式关系；
- 共同出现写成稳定联盟；
- support、project cost、NOFO、service presence 混成资金网络；
- 用来源密度表示组织活动强度；
- 用当前网络反推 1972 年以来的增长或连续性；
- 用颜色编码亲基地／反基地立场。

## 9. 模块归宿

R 模块是研究生产结构，不是前端栏目：

| 后端研究层 | 前端归宿 |
|---|---|
| R1／R2 | P2 组织—议题生态图 |
| R3／R4 | P1 全域地点—议题研究地图 |
| R5–R10 | P3 路径图的行动、场域与程序类型 |
| R11 | P2 的外来 actor 分面＋P3 的 entry-mode |
| R14 | 四页共用时间层；未审历史候选仅研究层 |
| coverage audit | P4 证据覆盖与偏差图 |
| source／evidence 基础层 | 全局证据抽屉 |

原方案扩展网页的八项内容被压缩为四页：

- 项目介绍 → 总览初始状态；
- 组织分类＋组织—议题 → 组织页；
- 地点—议题＋先岛专题 → 总览页；
- 国际倡议／法律程序 → 路径页；
- 方法＋下载＋更新日志 → 证据页的工具区。

## 10. NR-02 的输入与完成条件

NR-02 以本文件、`module_to_view_crosswalk.csv` 和 `view_visual_inventory_v1.csv` 为产品输入。
旧 wireframe 与 route map 不得被当作页面清单。

数据契约至少要证明：

1. 四个主图所需对象和关系都能由同一适配层生成；
2. 所有默认可见事实机械追到中央表与来源；
3. 候选、分析种子和 event-only 对象不会进入默认层；
4. 前端不需要为单个地区、组织或 episode 另写内容文件；
5. 同一选择状态可在四页间传递；
6. 重新构建结果稳定，且中央表无改动。

## 11. 检查点 A 决定记录

负责人已确认：

- 主展示页不超过五个，最终固定为四个；
- 采用第二张意向稿的“中央主图＋右侧详情＋底部时间层”方向；
- 首页从全域图开始，再进入地区、组织、路径与证据；
- 前端是后端数据与数据结构的自动化可视化，不准备大量页面文案；
- 一期五张核心图必须保留，但可收束进四个可视化引擎；
- NR-01 是可修订探索稿，不高于原始一期方案和负责人本轮决定。

NR-01 的页面与数据边界至此可作为 NR-02 输入。最终视觉对象、尺度、图例和交互细节继续在
可视化意向与最小纵向切片中验证，不再用线框数量代表完成。

## 12. 负责人修订记录（2026-07-19）

NR-03 美学检查点后，负责人对冻结结构做出以下修订，效力高于上文对应条款：

- **时间层改为第五个主页面**。原"四页共用底部时间层"（§3、§5）废止。时间页承载事件
  参与记录（按年份组织），悬浮底栏不再出现在任何页面。主导航因此为：总览、组织、
  时间、路径、证据（后两者仍为后续轮次）。
- **总览地图状态收窄为两个**：全域／先岛聚焦。原"严格证据"状态（§4 V1）被负责人否
  决；同源三元组改在右侧面板呈现，不再构成独立地图状态。
- **总览不显示证据深浅标记**。证据等级不编码在总览地图与区域标签上；证据等级仍保留
  在组织详情面板与（未来的）证据页。
- **建立字号规范**：11 overline／12 small／13 body／14 lead／19 h2／22 页标题／24 指
  标数字，界面文字不得低于 11px。
- **议题／地点标签按代码处理**。中、日、英三语映射将在数据层（NR-02 后续构建）以字
  段形式提供，前端只消费，不自行翻译。

## 13. 关系与证据状态修订（2026-07-20）

以下负责人决定覆盖本文关于“演示层”的旧称和关系状态的简化表述：

- 用户界面的“演示视图”改名为“已核视图”；内部 `demo/` 目录可暂时保留兼容；
- 已核视图允许 `supported_bounded`，但必须显示已确认字段、缺失字段和解释边界；
- 研究视图增加 candidate 和独立 research lead，不改变已核记录的措辞；
- evidence level、review status、human decision、claim status、graph eligibility 和
  display tier 分轴；
- 关系层不消费单一 edges 数组，使用 dyadic relation、case role、event participation、
  administrative record、aggregate observation、research lead 和 genealogy anchor；
- 颜色编码关系家族，箭头编码方向，实／虚线编码已核／候选；边宽和节点大小不编码证据、
  金额、关系强度或影响力；
- 证据不完整的记录可以展示，但不得只写“证据不足”，必须说明具体缺口。

权威规则见 `data/metadata/coding_schema_v1.md`、`docs/actor_relation_architecture_v1.md` 和
`docs/nr3_recheck_and_relation_frontend_brief_v1.md`。
