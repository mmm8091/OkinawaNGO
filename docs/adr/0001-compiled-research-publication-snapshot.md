# 采用编译式研究发布快照

项目在中央事实与展示前端之间增加一个编译式研究发布层：它按照明确的 release profile，
将已通过方法、证据和解释门禁的研究观察、主张、模块与展品编译为不可变的发布快照；前端
只渲染该快照，不再现场重算研究分类或拼接结论。不同 profile 生成到物理隔离的不可变
release 目录，构建先在 staging 中完成并验证，通过后才原子切换 channel 指针。当前数据规模、协作方式和
甲方访问场景不需要运行时写入、权限计算或查询，因此暂不增加后端、数据库或 API。

内部探索 builder 的 manifest 只证明 provenance，不授予发布资格。所有 core-derived
surface 另由逐路径／逐 JSON pointer registry 决定；混合关系包与候选包不能整体复制到公开
profile。

## Considered Options

- **前端直接消费中央表或多个研究输出**：拒绝。方法判断会散落在页面调用方，旧产出也容易
  因“文件存在”而被误当作可发布结论。
- **运行时后端统一查询**：暂缓。它能解决并发写入和动态权限，但当前没有这类需求，反而会
  增加部署、运维和复现成本；它也不能替代研究方法门禁。
- **单目录构建后覆盖**：拒绝。不同受众的字段可能互相泄漏，构建中断也可能留下半新半旧的
  混合发布物。

## Consequences

- 发布资格由方法与证据状态决定，而不是由前端需求或既有图表决定。
- client、internal research 等 profile 不共享发布目录；受限字段不依靠前端隐藏。
- 发布模块对外只暴露“编译快照”“验证快照”和“验证 channel”三个操作，读取、归一化、
  JSON pointer 投影、裁剪、追溯、哈希、不可变存储和 channel 激活都留在模块内部。
- 每次生产构建和每一代开发服务器都绑定一个已经验证的不可变 release；开发服务器监听
  channel，指针推进后整体重启并绑定新 release。这样并行请求不会跨两个快照混取记录。
- 纯静态站可以部署到对象存储与 CDN，并绑定公司域名；如果以后出现多写入者、动态权限、
  实时查询或服务端保密需求，再以新的 ADR 评估后端。
